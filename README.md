# Maison Amara, Makeup Atelier

A luxury, editorial website for a makeup artist studio serving Black women. React + Vite + Tailwind CSS v4, GSAP + ScrollTrigger, Lenis smooth scrolling, Lucide icons, React Router.

The signature is the opening: a full-screen film of a makeup application that **plays forward as you scroll down and backward as you scroll up**, with four chapters of editorial type moving over it, then a handoff to the rest of the page.

> **"Maison Amara" is a placeholder name.** Everything business-specific (name, contact details, hours, location, prices, durations, reviews, artist profile, policies) is clearly marked placeholder content. See [Before you go live](#before-you-go-live).

---

## Quick start

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # production build into dist/
npm run preview    # serve the production build on http://localhost:4173
npm run lint
```

Node 20+ is recommended. `ffmpeg` is only needed if you regenerate the hero film (see [Media](#media)).

## What is on the page

1. **Cinematic scroll-scrubbed hero** (4 chapters, one call to action)
2. Welcome (editorial introduction, asymmetric photography)
3. Services (editorial index with a sticky preview, not a card grid)
4. Gallery (masonry, category filters, full-screen viewer)
5. Transformation (before/after slider, keyboard and touch friendly)
6. The experience (pinned, scroll-driven appointment story)
7. Signature collections (The Signature is featured)
8. Meet the artist
9. Why choose us
10. Client love (sample reviews, labelled as samples)
11. Appointment **request** (5-step form, validation, honest confirmation)
12. Instagram-inspired strip (a static gallery, not a live feed, and labelled as such)
13. FAQ accordion
14. Final call to action
15. Footer, plus Privacy and Terms templates (`/privacy`, `/terms`)

## Editing content

All copy and structured content lives in `src/data/`. No component edits needed.

| File | What it controls |
| --- | --- |
| `site.js` | Studio name, descriptor, contact, Instagram, address, hours, nav, booking endpoint, JSON-LD switch |
| `services.js` | The 8 services, add-ons, time-of-day options. **Prices and durations are empty on purpose**: fill them in and they appear |
| `content.js` | Hero chapter copy, experience steps, collections, trust points, sample reviews, FAQ, before/after pairs, artist profile |
| `gallery.js` | Gallery categories and items, Instagram strip |
| `media.generated.js`, `hero.generated.js` | Generated by the media script. Do not edit by hand |

Colours and type are design tokens at the top of `src/styles/index.css` (`@theme`): ivory `#FAF7F2`, champagne `#E9DDD0`, dusty rose `#C78F98`, burgundy `#552B39`, espresso `#332724`, muted gold `#B99A6B`. Display type is Bodoni Moda, body type is Manrope (both self-hosted via Fontsource).

## Media

Every photograph and film is licensed stock from **Pexels** (commercial use, no attribution required, modification allowed). The exact sources and what that licence does and does not allow are in [`MEDIA-LICENSES.md`](./MEDIA-LICENSES.md). Mixkit was checked and rejected, because its free downloads are personal-use only.

**Important:** the people pictured are not clients or staff of this studio. The site labels them as inspiration, never as testimonials or as the artist. Replace them with the studio's own photography as soon as it exists.

### How media is built

`scripts/media.mjs` is a reproducible pipeline (sources are listed in `scripts/media-manifest.json`):

```bash
npm run media:fetch     # download sources into media-source/ (gitignored)
npm run media:images    # responsive WebP (480/960/1600) + src/data/media.generated.js
npm run media:hero      # scrub film (1080p + 720p), posters, mobile frame sequence
npm run media:stills    # the before/after demonstration stills
npm run media:og        # social card + touch icon
npm run media:licenses  # regenerate MEDIA-LICENSES.md
npm run media           # all of it
```

The hero film is encoded for scrubbing: a keyframe every 8 frames, no B-frames, `faststart`, graded warm, lightly denoised. It is fetched as a Blob (so scrubbing works on hosts without HTTP Range support) behind a progress ring, with a poster underneath and a captions-only fallback if it never loads. Phones and portrait tablets get a cropped, optimised **frame sequence on canvas** instead of video (more reliable on mobile). Reduced motion gets a composed still.

### Swapping in your own photography

1. Put your photos in `media-source/photos/` named `<id>.jpg`, and add entries to `scripts/media-manifest.json` (`key`, `id`, `alt`, `pos`).
2. `npm run media:images`, then reference the `key` in `src/data/*.js`.
3. For before/after, replace the pairs in `comparisons` in `src/data/content.js` with your own client photos (about 4:3 works best). Remove the "Demonstration only" note in `src/sections/Transformation.jsx`.
4. For the hero film, drop your footage in as the two masters named in the manifest (or edit `buildHero` in `scripts/media.mjs`) and run `npm run media:hero`.

## Appointment requests

The form never claims an appointment is confirmed. It sends a **request**, and the confirmation copy says so.

`src/lib/booking.js` is the only integration point:

- Set `VITE_BOOKING_ENDPOINT` (see `.env.example`) to POST the request as JSON to a form service (Formspree, Basin, a Netlify/Vercel function) or your own API. Visitors then see "Request received".
- Or replace the body of `submitBookingRequest` with a call to a scheduling provider (Calendly, Acuity, Square).
- Until one of those is set, and while the studio email is still a placeholder, the form runs in a **clearly labelled demo mode** and tells the visitor nothing was sent.

There is no fabricated live availability anywhere: date and time-of-day are preferences, not slots.

## SEO

- Unique title and description per page (`src/components/seo/Seo.jsx`), Open Graph and Twitter tags in `index.html`, `robots.txt`, `sitemap.xml`.
- **Replace `https://www.example.com`** in `index.html`, `public/robots.txt`, `public/sitemap.xml` and `src/data/site.js` with the real domain.
- LocalBusiness JSON-LD is **off** until you set `business.verified = true` in `src/data/site.js` and have filled in real details. No made-up business data is ever published.

## Deploying

It is a static site (`dist/`). Any static host works. Because it uses client-side routing, serve `index.html` for unknown paths: `public/_redirects` covers Netlify and Cloudflare Pages, `vercel.json` covers Vercel (and sets long-lived caching for `/media` and `/assets`).

## Performance and accessibility

Measured with Lighthouse 12 against the production build (`npm run preview`), default mobile throttling and the desktop preset:

| | Mobile | Desktop |
| --- | --- | --- |
| Performance | 81 | 100 |
| Accessibility | 100 | 100 |
| Best practices | 100 | 100 |
| SEO | 100 | 100 |
| FCP / LCP | 1.4 s / 2.3 s | 0.4 s / 0.5 s |
| TBT / CLS | 620 ms / 0 | 10 ms / 0 |

Lighthouse varies by a few points between runs (mobile LCP measured anywhere from 1.1 s to 2.3 s across runs). Mobile is Lighthouse's simulated mid-range phone on slow 4G with 4x CPU slowdown, which is deliberately harsh for a page with a film on it.

What makes that real rather than lucky:

- The hero poster is plain HTML, painted before any JavaScript. The app boots on the next frame.
- Everything below the film loads as a separate chunk and mounts progressively in idle slices.
- Entrances are CSS transitions flipped by one shared `IntersectionObserver` (no per-element layout reads). SplitText and parallax triggers are created lazily as elements approach the viewport.
- Images are WebP at three widths with intrinsic sizes (no layout shift) and `loading="lazy"`.
- Phones fetch a coarse set of frames first and the rest once scrolling starts. Save-Data keeps only the coarse set.

Accessibility: semantic landmarks and heading order, skip link, visible focus, focus-trapped menu and lightbox with focus return, ARIA slider for the before/after control, labelled form errors with focus management, 44 px touch targets on coarse pointers, and complete `prefers-reduced-motion` support that also reacts live if the setting changes while the page is open.
